# 경로 판정 규칙

변경 기록의 경로는 절대 경로이고, 문서에는 `/`로 구분해 적는다. task envelope의 범위 규칙은 작업 영역 기준 POSIX 상대 경로다. 요청의 `workspaceRoot`를 기준으로 기록의 경로를 상대 경로로 바꿔 규칙과 비교하고, 그 폴더 밖의 기록된 경로는 규칙과 비교하지 않고, 계획 파일이 아니면 `unplanned`로 본다. 절대 경로, `..`로 작업 영역을 벗어나는 경로, 해석되지 않은 환경 변수와 홈 축약은 범위 규칙으로 인정하지 않는다.

`scope.excluded`가 항상 우선한다. 허용 범위는 그 run의 현재 계획 파일, `scope.included`, 모든 `workUnits[].writeTargets`의 합집합이다. 정확한 파일, 디렉터리 접두사, `*`, `**` glob을 지원한다. 규칙이 자연어 설명이라 경로로 해석할 수 없으면 일치한다고 추측하지 않는다.

변경 목록은 기록이 마지막으로 남긴 상태를 기준선과 비교해 만든다. 기준선에 없고 지금 있으면 `created`, 기준선에도 있고 지금 다르면 `modified`, 기준선에 있었는데 지금 없으면 `deleted`다. 기준선과 같은 상태로 돌아온 경로는 변경으로 세지 않는다. 삭제는 삭제 전 경로가 허용되어야 한다. 기록의 root(write target) 자체가 링크이면 가리키는 실제 폴더를 읽어 기록하고(root가 읽히지 않으면 `unreadable:<경로>`다), root 아래의 symlink와 특수 파일은 따라가지 않으며 기록이 건너뛴 것으로 두고, 읽지 못한 경로는 `unreadable:<경로>` finding으로 남긴다.

규칙은 이름의 철자 그대로, 대소문자를 구분해 비교한다. 대소문자를 구분하지 않는 파일 시스템에서 다른 철자로 쓴 규칙은 일치하지 않을 수 있으므로 규칙은 파일 시스템이 돌려주는 철자로 쓴다. `workspaceRoot` 아래에 있는지는 이 컴퓨터의 파일 시스템 규칙으로 판단한다. 보고서에는 기록이 남긴 경로 철자를 그대로 보존한다.

이 검사가 보는 범위는 run의 변경 기록, 곧 write target 아래의 경로다. write target 밖의 경로는 기준선에 없고 변경도 기록되지 않으므로 보고서에 나타나지 않는다. 에이전트가 지원되는 편집 도구로 write target 밖을 직접 쓰면 편집 게이트가 막는다(게이트가 모든 쓰기를 잡지는 않는다). 빌드나 외부 프로그램이 write target 밖에서 바꾼 것은 이 검사가 보지 않는다.
