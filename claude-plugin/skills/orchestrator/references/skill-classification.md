# 스킬 분류 지원과 AGENT 선택

이 절의 분류 호출은 기존 승인된 설치 설정과 호스트 호출 경로에서 지원이 확인된 경우에 적용한다. 도구 노출·입력 스키마 가용성만으로 지원·인증·실행 관측을 추정하지 않는다. 미확정 상태에서 새 탐지 도구·호출 경로·설정 경로를 만들거나 분류를 원 작업의 필수 선행단계로 추가하지 않는다.

스킬 선택 지원이 설정된 환경에서는 `get_skill_inventory`로 registry provider와 실제 설치 스킬의 목록(요약)을 확인하고, 후보가 될 스킬의 적용·제외·의존성·source digest는 `skillIds`(한 번에 최대 6개)로 읽는다. 전체를 한 번에 읽으려 하지 않는다(응답이 호스트가 한 번에 읽을 수 있는 크기를 넘는다). 스킬 설명은 SKILL.md, provider의 capability·gate·단계는 registry, 구조화 taxonomy와 정확한 원문 참조는 각 스킬의 classification.json에서 읽는다. 외부 설치 스킬의 metadata가 없으면 누락을 보고하며 전체 목록을 검사했다고 주장하지 않는다. description이나 이름을 서버 프로그램에 복사해 두지 않는다.

`classify_skills`에는 사용자 원문과 출처가 확인된 context만 전달한다. 부정문·인용문·금지 행동을 보존하고 확인되지 않은 context는 null로 둔다. 별도 의미 요약 LLM을 호출하지 않는다. 앞단 포장은 결정적 처리이며 의미 해석은 분류 provider의 책임이다. 스킬 목록은 서버가 설치된 스킬에서 직접 읽으므로 에이전트가 넘기지 않으며 응답에도 되돌려 주지 않는다. 서버가 평가자에게 보내는 전체 후보와 dependency를 자르지 않는다. 응답의 점수는 평가자가 그 스킬에 내린 판정에 대한 확신도이며(not-needed에 0.98이면 거의 확실히 필요 없다는 뜻), 필요한 정도가 아니다. `advice`가 스킬마다 판정과 확신도를 함께 보여 준다. INPUT_TOO_LONG은 실제 누락 없이 보류한다.

JEV는 관리자 페이지에서 사용자가 서명한 설정(켜짐·모델·정보 전송 허용·예산)과 페이지에 등록한 key가 모두 있을 때만 사용한다. JEV가 꺼져 있거나 서명된 설정이 없으면 호출할 평가자가 없으므로 분류 호출을 하지 않고(JEV 호출 0회) 서버는 UNAVAILABLE(PROFILE_UNAVAILABLE)을 돌려주며 AGENT가 직접 고른다. JEV ON에서 통신 오류(연결 실패·끊김·응답 전 시간 초과·HTTP 429·5xx)는 같은 대상으로 간격을 늘려 다시 부르며, 횟수는 고정하지 않고 그 요청의 기한·예산과 공급자의 `Retry-After`가 상한이다. 기한·예산을 넘기면 멈추고 실패를 돌려준다. 키 없음·키 거부(401·403)·잘못된 응답 형식·그 밖의 4xx·너무 긴 입출력처럼 다시 불러도 나아지지 않는 오류는 다시 부르지 않고, 페이지에서 고른 대체 평가자(공급자와 모델)가 있으면 그 평가자를 부르며, 없으면 조언 없이 AGENT가 직접 고른다. 통신 오류가 끝내 풀리지 않은 경우에도 대체 평가자를 부르지 않고 AGENT가 직접 고른다. 이렇게 JEV가 조언하지 못한 뒤의 직접 선택은 `record_skill_selection`의 `selectionSource`를 `independent-agent-after-helper-failure`로 두어 기록하며, 서버는 이를 받아들인다(정보 전송을 허용하지 않았거나 예산이 없거나 작업이 바뀐 경우는 JEV의 실패가 아니므로 이 기록 대상이 아니다). OFF는 JEV 호출 0회이며 모든 분류 호출 금지가 아니다. JEV에는 qualification 관문이 없고 그 조언은 검증되지 않은 참고다. 외부 전송 허용(사용자가 서명한 「정보 전송 허용」)과 현재 예산은 호출마다 서버가 확인한다. native 구독 경로를 공급자 호출 허가(예: API 허가)나 비용 0으로 추정하지 않는다. 요청마다 모델 catalog·가격을 탐색하거나 임의 모델/effort 상향을 하지 않는다. 대체 평가자는 한 요청에 한 번만 부르고(그 평가자의 통신 오류 재시도는 같은 기한 안이다), 시도마다 예산을 따로 잡았다가 호출이 끝나면 푼다. 답을 받지 못한 호출은 비용으로 세지 않는다.

`jev`는 선택을 돕는 조언 계층의 자리이며 TypeSafe는 그 자리를 채우는 공급자 하나다. `noul_*` 점수 종류와 `JEV_*` 이유 코드는 TypeSafe adapter가 내는 값이고 계층 공통 의미가 아니다. JEV 예산은 사람이 정한 한도이고 서버가 따로 두는 상한은 없다. 그 한도는 답을 받은 호출의 추정액(이 PC의 모든 Sennard 서버가 남긴 기록의 합계)과 지금 보내는 호출의 예약액에 적용된다.

공통 RESP는 오류 가능한 분류 조언이다. 실제 원문, 명시 스킬, 조건부 필수, 실제 스킬의 적용·제외·dependency를 대조해 AGENT가 조언을 채택·교정·기각하고 **최종 선택**한다. 점수나 분류 결과를 정답·실행 승인으로 취급하지 않는다. 추천을 선택으로 복사하거나 과거 baseline을 무조건 union하지 않는다. raw 모델 누락은 규칙 보정 뒤에도 평가에서 그대로 실패로 남긴다. optional uncertainty가 독립적인 확정 작업 전체를 막지 않게 한다.

`record_skill_selection`에 AGENT가 고른 정확한 ID, 이유, 적용/제외 근거를 전달한다. hostReceipt는 null로 보내며 호스트 훅이 서명한 실제 호출 관측을 서버가 검증한다. 현재 request/task/config/profile/inventory revision이 다르거나 필수·명시·의존성이 빠지면 구체적 오류를 수정한다. 서버가 선택 집합을 대신 만들지 않는다. 실제 수락 전 selected는 null이며 실제 no-skill 정답을 수락한 경우만 []다. 미설치·비활성·미지원은 needed와 runnable을 구분한다.

호스트 훅·인증·판정불가 거부는 입력 스키마 오류나 분류 제공자 실패로 바꿔 해석하지 않는다. 원인·입력·설정이 달라지지 않은 같은 호출이나 실패와 무관한 도구·입력 형식 탐색을 반복하지 않는다. 구체적인 입력 오류는 확인된 필드만 수정한다. 분류·선택 기록이 수락되지 않았으면 미수락 상태를 유지한다. [MCP 실행·실패 처리](mcp-execution.md)에 따라 설치된 전문 스킬로 독립 처리 가능한 허용 부분은 직접 수행하고, 필수 관측·승인·통합·감사에 의존하는 단계는 보류한다. 직접 수행 결과를 선택 수락이나 보호된 통합·감사 완료로 기록하지 않는다. 기존 분류 제공자 전환과 서버가 허용한 실패 후 선택 기록은 유지하되, 훅 거부를 그 실패 근거로 사용하지 않는다.

선택은 실행 승인·본문 읽기·적용·검증 완료가 아니다. 기존 거버넌스 순서와 권한을 유지하고 각 스킬의 실제 본문·참조를 읽어 수행한다. selected/read/applied/verified는 동일 대상과 산출물 digest의 각 관측으로 기록한다. mode=shadow는 관측용이며 최종 select 동작을 대신하지 않는다.

JEV 설정은 관리자 페이지의 서명 기록과 Sennard에 내장된 공급자 정의로만 공급한다. 서명된 설정이 없거나 JEV가 꺼져 있으면 임의 기본 모델이나 호출 경로(예: API 경로) 없이 UNAVAILABLE(PROFILE_UNAVAILABLE)을 반환한다. 요청 원문·credential을 새 상태 DB나 로그에 저장하지 않는다. 독립 감사와 릴리스 승인은 기존 담당과 절차를 따른다.
