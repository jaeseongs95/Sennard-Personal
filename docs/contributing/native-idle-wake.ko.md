# Native 유휴 깨우기

서버는 수신 대상과 세대마다 미완료 nonce를 하나만 예약한다. 추가형 V23 마이그레이션은 `native_wake_reservations`를 만들고 messaging 모듈을 버전 5로 올린다. `wake_paths`는 peer 메시지를 인수한 경계를 기록한다.

서버가 등록 키를 응답에 돌려주면 설치된 훅 클라이언트가 Sennard JAR로 로컬 워커를 시작한다. Codex는 `SessionStart`와 유휴 `Stop`에서 키를 보낸다. Antigravity는 Sennard MCP 호출의 대화 ID·도구·인자가 앞선 훅과 일치해 메인 대화로 확인된 뒤 등록할 수 있다. `Stop`은 처리를 이어 갈 수 있었지만 연장 없이 끝난 경우에 등록할 수 있다. 워커가 시작 중이거나 메인 대화의 연결이 유효하면 이후 유휴 `Stop`에서도 해당 워커를 사용한다. 관리형 자식만 지원하던 연결에 유휴 `Stop`으로 메인 대화의 깨우기를 추가해도 기존 자식은 원래 워커와 ACP 연결을 사용한다.

워커는 서버가 키를 돌려준 훅에서 대상과 설정을 얻고 루프백 요청으로 예약 표식을 받는다. 이후 `SessionStart`에서 등록하면 기존 연결을 교체한다. 워커는 관리형 자식을 지원하는 중에도 메인 대화 깨우기 상태를 정해진 값인 `DISABLED` 또는 `MISSING`으로 보고할 수 있다. 사용할 연결이 없으면 메시지는 일반 인수 경계까지 큐에 남는다. Claude Code는 사람이 붙어 있는 대화형 세션의 비동기 대기 훅으로 깨운다. `-p` 세션은 대기 단계를 건너뛴다.

유휴 연결을 교체할 때 기존 워커가 자식을 소유하고 있거나 자식을 생성 중이면 연결을 유지한다. 자식과 진행 중인 생성 요청이 모두 없어지면 기존 연결을 닫는다. 워커는 등록 시점 또는 마지막으로 수락된 폴링 요청부터 30초 안에 다시 폴링해야 한다. 시간이 지나면 등록 키가 만료된다. 자식의 세션과 세대가 여전히 유효하면 이미 받은 표식을 인수할 수 있다.

서버는 호스트가 처리를 이어 갈 수 있는 이벤트에서 에이전트가 멈추면 대상을 유휴 상태로 본다. 메시지가 큐에 커밋되면 로컬에서 감시한 소유자와 데이터베이스의 현재 세대를 확인하고 알림을 보낼 수 있다. 서버는 `STARTED`를 커밋한 뒤 단일 요청에 표식을 전달한다. Worker는 native 명령을 직접 실행하고 해당 표식과 정해진 결과값을 돌려준다. `SUBMITTED`는 CLI에 인계했음을 기록한다. 인계 후 응답 유실, 모호한 비정상 종료, 시간 초과 또는 명령 시작 후 실패의 결과는 `UNKNOWN`이다. 전송되지 않았음이 확인되면 5초 뒤 새 메시지나 경계에서 재시도할 수 있다.

훅 처리 경로는 일반 입력 처리보다 먼저 `[sennard wake:<uuid>]`를 검사한다. 세션과 세대가 활성 상태이고 nonce와 서버 실행 인스턴스가 일치해야 인수할 수 있다. 표식 소진, peer 본문 인수와 출처 영수증 생성은 한 트랜잭션에서 처리한다. 재사용·퇴역·무효 표식과 이전 서버가 발급한 표식으로는 본문을 인수할 수 없다. 정상 입력은 기존 첫 경계 유예를 유지한다.

본문 인수나 ACK를 관측하면 다음 알림을 예약할 수 있다. 정상 native 입력이 들어오면 70분 지난 불확실한 시도를 퇴역시킬 수 있다. 관측하지 못한 `STARTED`·`SUBMITTED`·`UNKNOWN`은 재시작 뒤에도 남는다. 복구는 현재 소유 중인 세션과 세대에서 실행을 시작하지 않은 예약을 취소하고 이전 `STARTED`를 `UNKNOWN`으로 전환한다. 서버나 세션이 종료되면 연결을 닫고 접근 키를 무효화한다.

## 호스트 요구 사항

- Codex 대기열 깨우기는 기본으로 켜져 있다. 워커는 `SENNARD_CODEX_QUEUE_WAKE`가 설정되어 있으면 그 값(`0`은 끄기, `1`은 켜기)을 사용한다. 변수가 없으면 절대 경로 `PLUGIN_DATA/session-messaging.json`의 `codex.queueWake`를 읽는다. 파일 제한은 4096바이트이며 `{"schemaVersion":"1.0.0","codex":{"queueWake":false}}`처럼 `queueWake` 값은 JSON 불리언이다. 변수 값이 비어 있거나 잘못된 경우, 또는 적용할 파일을 읽을 수 없거나 형식이 잘못된 경우에는 사전 조건 누락으로 보고한다. 워커는 관리 패키지 폴더나 훅의 PATH에서 네이티브 실행 파일을 찾아 `queue --thread <session> --message <marker>`를 호출한다.
- Antigravity는 절대 경로인 `ANTIGRAVITY_AGENTAPI_EXE`나 훅의 PATH에서 native 실행 파일을 찾는다. `ANTIGRAVITY_CONVERSATION_ID`가 있으면 관측한 대화와 일치해야 한다. 대화형 메인 세션에서 `agentapi send-message <conversation> <marker>`를 호출할 때는 `ANTIGRAVITY_PROJECT_ID`, `ANTIGRAVITY_CSRF_TOKEN`과 루프백 `ANTIGRAVITY_LS_ADDRESS`가 필요하다. 주소에는 `localhost`, 표준 표기의 IPv4 루프백 주소 또는 `[::1]`와 1~65535번 포트를 쓸 수 있다.
- Antigravity 관리형 자식을 만들 때 워커는 메인 세션의 작업 폴더에서 `agy acp`를 시작해 호스트가 지원하는 모델과 추론값을 확인한다. ACP 연결이 살아 있는 동안 호스트가 반환한 대화 ID를 유지하며, 첫 훅부터 워커가 등록한 결속을 사용한다. ACP 요청에는 예약 표식만 넣고 서버는 호출 직전 훅으로 peer 메시지를 제공한다. ACP 제어 요청은 10초, 수신 프레임은 1 MiB로 제한한다. 호스트의 기존 MCP 권한 규칙을 적용하며, 사용자 확인이 필요한 요청은 워커가 취소한다.

네이티브 `agentapi` 호출은 10초와 출력 64 KiB로 제한한다. 깨우기 요청으로 등록 키, 기능, 정해진 상태값, 표식과 결과를 교환한다. 허용 목록에 있는 호스트 환경과 연결 토큰은 로컬 워커와 네이티브 자식 프로세스에만 남는다.

서버와 훅 클라이언트를 함께 갱신하고 새 훅 정의를 적용한다. 1.3에서 1.4로 올릴 때 설치 프로그램만 `AGENT_GOVERNANCE_CODEX_QUEUE_WAKE`를 읽어 이전 상태를 확인한다. 1.3에서는 이 변수가 있으면 값이 `1`일 때만 깨우기가 켜졌다. 변수가 없으면 활성 사본별 플러그인 데이터 파일을 사용했고 기본값은 꺼짐이었다. 사본 하나라도 꺼짐에서 켜짐으로 바뀌면 CMD와 설치 창에서 한 번 확인한다. 거절하거나 확인할 수 없으면 버전, 서버, 설정을 변경하기 전에 중단한다. 새 변수가 없으면 설치 잠금 상태에서 설정을 다시 확인하고 필요한 파일만 원자적으로 교체한다. 새 `SENNARD_CODEX_QUEUE_WAKE=0`을 설정하면 깨우기가 꺼져 있고 파일을 그대로 둔다. [업그레이드 절차](../user/update.ko.md#업데이트-절차)

설정을 바꾼 뒤에는 수신 세션을 다시 연다. Codex와 Antigravity는 다음 적격 `Stop`에서 새 서버에 등록할 수 있다. 이미 쉬고 있는 세션은 한 턴을 실행해 그 경계에 이르거나 다시 열어야 한다. 되돌릴 때는 서로 맞는 서버와 훅 클라이언트 버전을 복구하고 세션을 다시 연다. 실제 호스트의 깨우기는 표식 입력, peer 메시지 인수와 ACK를 관측해 확인한다.
