# Native idle wake

The server reserves one outstanding nonce per recipient and generation. The additive V23 migration adds `native_wake_reservations` and advances the messaging module to version 5. `wake_paths` records the boundary at which the peer message is claimed.

The installed hook client starts a local worker from the Sennard jar when the server echoes the registration key. Codex offers a key at `SessionStart` and at an idle `Stop`. An Antigravity conversation can register once a Sennard MCP call matches the conversation ID, tool and arguments of its preceding hook and establishes it as the main conversation. An eligible `Stop` allows continuation and ends without one. Repeated idle stops keep a starting worker or a live main-conversation relay. When an eligible `Stop` adds main-conversation wake to a managed-only registration, existing children keep their original worker and ACP connection.

The worker takes its target and configuration from the accepted hook and polls the server over loopback for a reservation marker. A subsequent accepted session start replaces the relay. A registered worker can report the fixed root wake status `DISABLED` or `MISSING` even if it can still manage children. Messages stay queued for ordinary claim boundaries when a usable relay is unavailable. Claude Code uses an asynchronous wait hook in attended sessions. Its `-p` sessions skip the wait.

On an idle relay replacement, the old worker stays connected while it owns a child or has a child launch in progress. The service releases the old connection when no children or launches remain. A worker must poll within 30 seconds of registration or its last accepted poll. Expiry invalidates the registration key. A child can still consume a marker that was already offered if its session and generation remain valid.

The server treats a target as idle when the agent stops at an event where the host could have continued processing. A committed queue event can then dispatch against the locally watched owner and the live database generation. The server commits `STARTED` before offering the marker to one poll. The worker executes the native command directly and returns a fixed outcome for that marker. `SUBMITTED` records CLI handoff. A lost response after handoff, ambiguous nonzero exit, timeout or post-start failure leaves the outcome `UNKNOWN`. A confirmed non-send can be retried after five seconds at a later message or boundary.

The hook pipeline intercepts `[sennard wake:<uuid>]` before the ordinary input consumers. Consumption requires the live session and generation, the matching nonce and the current server incarnation. The transaction consumes the marker, claims the peer body and creates its source receipt. Replayed, retired, invalid and previous-server markers claim nothing. Normal native input retains its ordinary first-boundary deferral.

A body claim or ACK rearms the reservation. Normal native input can retire an uncertain attempt after 70 minutes. The server retains unobserved `STARTED`, `SUBMITTED` and `UNKNOWN` across restarts. Recovery cancels a reservation that never started and converts an older `STARTED` to `UNKNOWN` for the current owned session and generation. A server or session shutdown closes the relay and invalidates its capability.

## Host requirements

- Codex queue wake defaults to on. The worker uses `SENNARD_CODEX_QUEUE_WAKE` (`0` disables, `1` enables) when present. Otherwise it reads `codex.queueWake` from the absolute `PLUGIN_DATA/session-messaging.json`. The file limit is 4096 bytes. The `queueWake` field takes a JSON boolean, as in `{"schemaVersion":"1.0.0","codex":{"queueWake":false}}`. An empty or invalid value for the variable, or an unreadable or invalid file when it is consulted, reports missing prerequisites. The worker finds a native executable in the managed package directory or on the hook’s PATH and invokes `queue --thread <session> --message <marker>`.
- Antigravity resolves the native executable from an absolute `ANTIGRAVITY_AGENTAPI_EXE` or the hook's PATH. If present, `ANTIGRAVITY_CONVERSATION_ID` must match the observed conversation. For interactive main sessions, `agentapi send-message <conversation> <marker>` also requires `ANTIGRAVITY_PROJECT_ID`, `ANTIGRAVITY_CSRF_TOKEN` and a loopback `ANTIGRAVITY_LS_ADDRESS` using `localhost`, canonical IPv4 loopback or `[::1]`, with a port from 1 to 65535.
- For Antigravity managed children, the worker starts `agy acp` in the main session's workspace, checks the host's model and reasoning options and keeps ownership of the returned session ID for the life of the ACP connection. The first accepted hook uses the worker's existing binding. The worker uses the ACP connection to launch and manage the child. PEER wake applies only to confirmed main sessions. ACP control exchanges have a ten-second deadline and inbound frames are limited to 1 MiB. The host applies its existing MCP permission rules and the worker cancels interactive permission requests.

Native `agentapi` invocations have a ten-second deadline and a 64 KiB output limit. Wake requests exchange registration keys, capabilities, fixed status values, markers and outcomes. The allowlisted host environment and connection tokens stay in the local worker and native child.

Upgrade the server and hook client together and apply the updated hook definitions. During a 1.3 to 1.4 upgrade, only the installer reads `AGENT_GOVERNANCE_CODEX_QUEUE_WAKE` to determine the previous setting. If present, only `1` enabled 1.3 wake. Otherwise each active copy used its own plugin data file and defaulted to off. CMD and Setup ask once if any copy will switch from off to on. Declining or being unable to confirm cancels the upgrade before setup changes the version, server, or settings. If the new variable is unset, setup makes the necessary file updates under the install lock, checking the settings again before atomically replacing the files. A new `SENNARD_CODEX_QUEUE_WAKE=0` keeps wake off and leaves the files alone. [Upgrade procedure](../user/update.md#update-procedure)

Reopen the receiving session after changing its settings. Codex and Antigravity can register with the new server at the next eligible `Stop`. An already idle session needs a turn to reach that boundary, or it can reopen. Restore matching server and hook client versions and reopen the session to roll back. Confirm wake in each real host by observing the marker input, peer claim and ACK.
