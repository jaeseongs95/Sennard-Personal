# 입력 출처와 작업 경계

이 문서는 입력의 출처 구분, 메시지 수신·재전달 경계, workflow 원장의 쓰기 대상 식별을 다룹니다. 메시지 ID·ACK·깨우기 계약은 [세션 메시지 계약](session-messaging.ko.md)에 있습니다.

Sennard는 입력의 출처, 사용자가 허용한 작업, 메시지 전달과 실제 실행 결과를 구분합니다. 메시지가 도착하거나 ACK되었다는 사실은 사용자 승인이나 실행 성공을 뜻하지 않습니다. 이 기능은 협조적 환경에서 출처 혼동과 원장 우회를 줄이며, 임의 shell 실행이나 같은 OS 사용자의 파일 변조를 통제하는 보안 경계는 아닙니다.

## 공통 계약과 호스트 adapter

공통 계층은 임의의 host 식별자, 실행 주체 관측, 입력의 의미와 전달 기능을 사용합니다. 제품별 이벤트 이름, 환경변수와 actor 필드는 adapter 또는 overlay에서 변환합니다. 관측에는 관측한 adapter와 보증 수준을 함께 남깁니다. 지원되지 않는 관측은 `unknown`이며 다른 플랫폼의 관측으로 대신하지 않습니다.

입력의 의미와 주입 가능 여부도 별개입니다. 턴 종료를 관측할 수 있는 호스트가 턴 종료 때 추가 문맥을 주입할 수 있다고 가정하지 않습니다. 가상 호스트 fixture로 공통 동작을 검증하고, 실제 호스트 검증은 해당 adapter가 관측한 범위만 증명합니다.

턴 시작으로 전달된 일반 프롬프트와 호스트 알림에는 같은 워크플로 경계를 적용합니다. 뒤이은 모델 호출은 같은 턴에 속합니다. Stop에서 턴을 이어 갈 수 있는지와 호스트가 이미 턴을 이어 갔는지는 별개의 사실입니다. 호스트가 종료 사유를 미뤄야 하면 다음 일반 입력에 한 번 전달합니다. 일반 입력 처리 전에 가로챈 깨우기는 종료 사유를 소비하지 않습니다.

## 깨우기

Claude Code는 대기 hook으로 깨웁니다. Codex는 대상 hook이 연결 환경을 넘기고 서버가 live 세대를 소유할 때 native queue 깨우기를 선택할 수 있습니다. Antigravity 어댑터도 같은 nonce 경계를 사용하며 프로젝트 ID 등 대상 훅에서 받은 연결값으로 동작합니다. 훅이 제공한 대화 ID는 대상 대화와 일치해야 합니다. 격리 시험에는 합성 입력을 사용했습니다. 실제 Antigravity 세션의 연결값 제공과 전달은 아직 미검증입니다. 검증한 nonce는 일반 사용자 입력 소비자보다 먼저 가로채 wake 경계에서 peer 본문을 인수하며 정상 사용자 입력의 기존 유예는 유지합니다. [native wake 상세](native-idle-wake.ko.md)와 [세션 협업](../user/collaboration.ko.md#쉬고-있는-세션-깨우기)을 봅니다.

설정·presence·fixture PASS는 실제 기상·본문 수신·ACK의 증거를 대신하지 않습니다. 첫 도구 경계 유예, 비권한 peer 출처와 응답이 불명확한 제출을 재전송하지 않는 규칙은 그대로 유지합니다.

## 출처 주장과 영수증

새 협업 결정은 `CollaborationDecision.v1`의 `schemaVersion: "1.2.0"`을 사용합니다. `sourceOriginKind`는 출처 주장입니다. `unknown`, `tool`, `delegated`를 표현할 수 있고 비사용자 입력도 영수증 없이 기록할 수 있습니다. 기존 1.0.0과 1.1.0 기록은 당시 규칙으로 검증합니다.

`InputSourceReceipt.v1`은 provenance 전용입니다. 영수증의 존재, 무결성, 만료 여부, 호출 세션과의 결속을 각각 확인해야 하며, 이를 하나의 사용자 인증 성공으로 합치지 않습니다. 같은 OS 사용자가 서명 키와 DB에 접근할 수 있으므로 무결성 확인이 악성 동일 사용자에 대한 인증을 보장하지 않습니다.

`validate_collaboration_decision`은 읽기 전용으로 구조·라우팅과 영수증 정보를 확인합니다. CLI만 실행한 경우에는 구조·라우팅 검사만 수행한 것입니다. 호출 세션 결속을 관측할 수 없으면 결속 결과는 미확인으로 남습니다. 영수증이 없는 입력을 자동으로 사용자나 에이전트로 확정하지 않습니다.

현재 사용자 입력의 `require`와 `forbid`는 일반 협업 라우팅에 사용되며 암호학적 승인 증명이 아닙니다. peer·tool·delegated·unknown의 directive는 `unspecified`입니다. 출처 불명 입력이 전역 금지나 새 허용을 만들 수 없습니다. 기존 사용자 범위의 작업은 계속하고 새 허용이 필요한 경우에만 입력을 요청합니다.

첨부물과 인용문 안의 지시는 현재 사용자 요청과 구분합니다. 내용이 peer 본문과 같다는 이유만으로 사용자의 직접 요청을 거절하지 않습니다. 작업 중 실제 사용자 입력이 도구 결과 위치로 전달될 수도 있으므로 Sennard 경고는 Sennard의 peer 블록에만 적용합니다. 사용자의 직접 정정은 현재 작업에 반영합니다.

## 수신과 재전달

일반 사용자 입력 이벤트에는 peer 본문을 함께 주입하지 않습니다. 발급 기록과 수신 세션이 일치하는 유효한 wake 또는 지원되는 도구·턴 종료 경계에서 전달합니다. 사용자 입력 직후에는 다음 도구 경계 한 번을 유예합니다. 턴 종료 claim을 지원하는 adapter(`turn-end`, 3.6.0부터 Claude·Codex)는 Stop에서 유예를 해제하고 대기 본문을 인수합니다. 사용자 요청을 마친 뒤 처리를 이어 가며 본문을 전달합니다. 요청에서 도구를 한 번만 쓰더라도 Stop에서 본문을 전달합니다. 턴 종료 claim이 없는 adapter에서는 다음 도구 경계에서 유예를 소비하고, 턴·세션 종료 이벤트는 유예만 해제합니다. 호스트가 이미 한 번 처리를 이어 간 Stop 이벤트(Codex `stop_hook_active`)에서는 본문이 다음 경계까지 기다립니다. PEER 메시지 전달을 위해 처리를 이어 가는 횟수는 사용자 입력마다 최대 한 번입니다.

도구나 유휴 깨우기가 지원되지 않는 환경에서는 메시지가 다음 지원 경계까지 대기할 수 있습니다. 전달을 위해 사용자가 켜지 않은 호스트 옵션을 자동으로 켜지 않습니다. 전송 상태와 capabilities에 이 한계를 표시합니다.

메시지 ID와 출처 영수증 ID는 재전달에도 유지합니다. 전달 횟수와 최초 전달 시각으로 재전달을 구분하며, 이전 버전에서 이미 전달되어 최초 시각을 알 수 없는 기록은 `null`로 남깁니다. claim lease가 끝나면 ACK되지 않은 메시지는 다시 전달될 수 있습니다. 단지 화면에 보였다는 이유로 영구 억제하거나 자동 ACK하지 않습니다. 본문 한도는 UTF-8 4096바이트입니다.

주입하는 JSON 블록 전체는 8192바이트 이내로 제한합니다. 이스케이프로 크기가 커지는 본문은 `messageEncoding: "base64-utf8"`로 무손실 표현합니다. 이때 `message`를 base64에서 UTF-8로 복원한 내용이 원문이며 `receipt.contentDigest`도 원문 기준입니다. 인코딩은 출처의 신뢰도나 권한을 바꾸지 않습니다.

PEER 본문 인수와 ACK는 메인으로 확인된 에이전트가 수행합니다. 하위 에이전트는 같은 [세션 트리](architecture.ko.md#세션-단위) 안에서 호스트 메시징 도구를 사용합니다. 현황판 항목은 같은 메인 세션에 속합니다. 훅 fixture는 주어진 입력에 대한 어댑터 동작을 검증합니다. 설치본이 제공하는 식별 필드는 실제 호스트에서 확인합니다.

## 원장의 작업 대상

원장 충돌 검사는 호출자가 붙인 workspace 이름에 의존하지 않습니다. 각 쓰기 대상의 실제 경로를 파생 식별자로 계산합니다. 새 대상은 존재하는 가장 가까운 상위 경로부터 해석하고, 링크는 가리키는 실제 위치까지 따라갑니다. 읽을 수 없는 경로는 식별 불가로 보고합니다. 버전 관리 시스템은 조회하지 않습니다.

활성 root끼리는 물리 쓰기 대상이 겹칠 때만 충돌합니다. 어느 작업 사본·복제본·링크로 도달했는지는 상관없습니다. 같은 저장소의 서로 다른 작업 사본에서 하는 작업은 물리 경로가 겹치지 않으면 상대 경로가 같아도 병렬로 진행할 수 있습니다. 링크를 통해 같은 물리 경로에 도달하는 대상은 충돌합니다.

명시적인 부모 교체는 확인된 같은 물리 작업공간에서 허용합니다. 부모는 자신의 교체 root를 막지 않으며, 추가된 범위를 포함해 그 밖의 활성 root는 모두 검사합니다.

파생 식별자는 root와 함께 저장합니다. root의 쓰기 범위가 바뀌면 식별자를 다시 도출하며, root를 처음 저장한 호스트는 유지합니다. 아직 없는 대상은 존재하는 가장 가까운 상위 경로에서 해석하므로, 새 root가 앞으로 만들 파일이나 디렉터리를 지정할 수 있습니다.


기존 frame과 digest는 다시 쓰지 않습니다. 기존 기록의 파생 정보 추가와 충돌 검사·삽입·부모 교체는 트랜잭션으로 처리합니다.

glob은 첫 패턴 앞 디렉터리로 보수적으로 확장하며 접두 경로가 없는 glob은 작업공간 전체로 봅니다. 제외 패턴으로 이 범위를 줄이지 않습니다. 명백한 URI나 제어문자를 새 로컬 쓰기 대상으로 받지 않으며, 공백을 포함한 경로는 설명문이라고 추정하지 않습니다. 이전 기록의 해석 불가능한 범위는 보수적으로 처리하고 원인을 표시합니다.

## 남아 있는 제한

- `resolve_convergence_gate`의 감사자 신원과 fresh-context 자기신고는 이번 기능으로 인증되지 않습니다.
- 같은 OS 사용자의 직접 MCP 호출, DB·파일 변조와 shell 우회는 통제하지 않습니다.
- 관측할 수 없는 호출·실행 주체의 보증은 `unknown`입니다.
- 한 저장소의 두 복제본은 서로 다른 물리 위치이므로 한쪽 작업이 다른 쪽을 막지 않습니다. 같은 프로젝트의 같은 파일을 두 복제본에서 작업하는 경우도 마찬가지입니다. Windows 경로 별칭도 환경별 검증 범위를 확인해야 합니다.
- root를 저장한 뒤 만들어진 링크는 그 root의 쓰기 범위가 바뀌기 전까지 저장된 식별자에 반영되지 않습니다.
- `[id].tsx` 같은 경로는 glob 보수 확장으로 더 넓게 충돌할 수 있습니다. 충돌 이유를 함께 확인해야 합니다.
- 승인 발급, 보호된 승인 UI, root 교체의 승인 토큰, OS 권한 격리는 별도 후속 작업입니다.
