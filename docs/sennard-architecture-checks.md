# Sennard architecture checks

The build enforces the architecture rules. Each rule counts violations in the current code and uses that number as its ceiling.
A count above the ceiling fails the build. [한국어판](sennard-architecture-checks.ko.md)

## Where they run

- `sennard-arch-checks` (Gradle module, test sources only): `./gradlew :sennard-arch-checks:test`. One check class alone: `./gradlew :sennard-arch-checks:test --tests '*ArchitectureRulesTest'`.
  The module reads the sources, SQL and build scripts of every module as files and their compiled classes with ArchUnit, so it needs neither the app image nor PostgreSQL.
- `sennard-store-pg`, `ForeignKeyCatalogTest` (rule k): it reads the schema on the configured test PostgreSQL and lives with the other business-database tests.
- Both run in `./gradlew test`.

## Tools chosen

| Need | Choice | Why |
| --- | --- | --- |
| Package dependency cycles | ArchUnit 1.5.1 (`com.tngtech.archunit:archunit`) | Rule a counts pairs of packages that depend on each other; Spring Modulith `verify()` works on application modules (the direct sub-packages of the package of the `@SpringBootApplication` class) and reports module cycles only. Modulith 2.1.1 is built against Spring Boot 4.1.1 (`spring-modulith-core-2.1.1.pom`, `spring-boot-autoconfigure:4.1.1`) so it is compatible with 4.1.2 by release line (an inference from the pom; the Modulith documentation has no compatibility table), but `sennard-server` and the `sennard.service.*` modules have no application class, and package level pairs are not what it checks (Spring Modulith reference, Fundamentals and Verification). ArchUnit's slices (`slices().matching(...).should().beFreeOfCycles()`, ArchUnit user guide 8.2) and its dependency model do. |
| ArchUnit version | pinned in `sennard-arch-checks/build.gradle.kts` | Neither the Spring Boot 4.1.2 BOM nor any BOM the project applies manages it (`spring-boot-dependencies-4.1.2.pom` has no `com.tngtech` entry). 1.4.1 added Java 25 class files (ArchUnit release notes). |
| Rules on Java source | the JDK compiler API (`jdk.compiler`, `com.sun.source`) | Parsing only; no dependency, no access to JDK internals. A rule works from the names written in the source, not from types (see Limits). |
| Rules on SQL | text with comments and string literal contents blanked out | A word in a comment or literal is never counted. |
| Error Prone | not added now | The rules here are not Error Prone checks. Error Prone must open javac internals with `--add-exports`/`--add-opens` on JDK 16 and later (Error Prone installation guide, tbroyer/gradle-errorprone-plugin README), which the project does not allow elsewhere, and its new warnings under `-Werror` would widen the rewrite. javac stays at `-Xlint:all -Werror`. |
| Versions of libraries | the Boot BOM | Spring Boot reference, Build Systems, Dependency Management: "you do not need to provide a version". Rule h checks it. |

## Ceilings

`sennard-arch-checks/src/test/resources/ceilings.properties` holds every ceiling except k (`ForeignKeyCatalogTest.CEILING`). A rule fails above its ceiling and
also below it ("lower the ceiling to N"), so a ceiling is lowered by a person when the code improves and never leaves room for a new violation to take the place
of a fixed one. A failing rule prints every `file:line` of its violations.

## Limits (what the checks do not see)

- Source rules work on syntax. A name that only the compiler resolves is invisible: a string constant of another class in `equals`, a type reached through an alias or a
  method result (rule d judges a collection by the declared type and the initializer), a logger held in a variable whose name does not contain `log` (rule f).
- Rule n and the SQL rules read the SQL that is written as strings in the code. SQL assembled at run time from values (a table name chosen by a method result, a fragment
  returned by a helper) is read only as far as its literal parts, and a statement built entirely at run time is not seen.
- Rule k misses a reference whose column is named differently from the key it points at (`sender_ref`, `target_ref` for `session_ref`) and a reference to a key whose name does not end in
  `_id` or `_ref`. It can name a wrong target when several tables have a key of that name.
- Rule h treats the groups of the imported BOMs as managed; a library of such a group that the BOM does not list is reported wrongly.
- Rule g-string-equals counts every word-like literal, including strings of an outside format (an HTTP method, an MCP method name), which the rewrite keeps at the
  boundary only.

## Cases of the checks themselves

`RuleFixturesTest` holds, for each rule, a source that breaks it and a source that keeps to it, including the near misses a rule must leave alone (a logged or rethrown
catch, an enum switch, immutable constants, `max`/`min`/`coalesce` in SQL, a word inside an SQL comment or literal). The check of rule a compiles two small packages that
refer to each other and one that does not.
