# 결함 수정 작업 규칙

적용 조건: 사용자가 보고한 결함(잘못된 결과, 오류, 실패하는 시험, 화면이나 출력에서 본 증상)을 고치라는 요청, 또는 이미 고쳤다고 한 결함이 다시 나왔다는 요청.

1. 결과물을 고치기 전에 사용자가 본 증상을 사용자가 쓰는 진입점에서 재현한다. 재현에 쓴 명령(또는 절차)과 그 출력을 그대로 남긴다.
2. 재현이 되면 깨진 위치를 `파일:줄`(결과물이 파일이 아니면 그에 맞는 위치)로 특정하고 무엇이 왜 깨졌는지 한 문장으로 쓴 뒤에 고친다. 깨진 조건이 있는 자리에서 고친다. 증상만 가리는 수정(오류·예외 삼키기, 값 고정, 시험 기대값 바꾸기, 해당 경로 건너뛰기)은 수정으로 세지 않는다. 같은 원인을 쓰는 다른 경로가 있는지 찾아 확인한다.
3. 고친 뒤에 1에서 쓴 명령을 같은 형태로 다시 돌리고, 전과 후의 출력을 나란히 보고한다.
4. 재현을 못 했으면(환경, 권한, 재현 불가) "고쳤다"고 쓰지 않는다. 시도한 것, 막힌 이유, 확인하지 못한 것을 보고한다.
5. 같은 증상이 재발했거나 사용자가 아직 안 고쳐졌다고 하면 새로 고치기 전에 이전 수정이 왜 그 증상을 막지 못했는지를 먼저 쓴다. 이전 수정 위치와 이번에 깨진 위치가 다르면 그 차이를, 같으면 이전 수정의 확인이 무엇을 보지 못했는지를 쓴다.
6. 이 작업에 해당하는 스킬(Sennard 접수 안내가 가리키는 스킬)의 `SKILL.md`는 직접 열어 읽고 절차를 따른다. 열지 않았다면 열지 않았다고 보고한다.
7. 끝내는 보고에 재현 명령과 전 출력, 깨진 위치, 같은 명령의 후 출력, 확인하지 못한 것을 쓴다.

이 호스트에서는 파일을 고친 턴이 마지막 수정 뒤 명령 실행 없이, 또는 `SKILL.md` 읽기 없이 끝나려 하면 한 번 이어 가게 된다. 이어 가면 위 3, 4, 6을 한다.
